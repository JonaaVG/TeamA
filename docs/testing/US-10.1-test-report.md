# US 10.1 - Treatment-code import: test report

Date: 19 November 2026. Branch: `US-10.1-Zorgbehandelingenbestand-inlezen`.

## Implemented behaviour

An authenticated `SystemAdministrator` can select and import an Excel (`.xlsx` or `.xls`) or CSV (`.csv`) file at `/admin/treatment-codes/import`. The page follows the supplied desktop wireframe and also works on a small screen. The existing login, JWT API client, router and SQL schema are reused.

The source header is `Zorgcode, Omschrijving, Specialisme, Tijdsduur (kwartieren), Kosten (€)`. One data row represents one treatment code. Duration remains a number of quarters; it is not converted to minutes. Costs are stored as `decimal(10,2)`. Required fields must fit the existing database constraints. Uploads are limited to 10 MB and 10,000 treatment rows.

The original source is a comma-separated CSV with 100 records and can be imported directly. CSV files may use commas or semicolons as separators. Each data row must have the same number of fields as the header so that, for example, an unquoted decimal comma cannot silently change a price. PDF files and text files renamed to an Excel extension are rejected.

## Running the checks

Use .NET 11, the project's Node/npm requirements and the existing GentleHealers database schema. Configure `ConnectionStrings:DefaultConnection` and the existing JWT settings for the intended local environment. Do not run the data seeder repeatedly.

From the repository root:

```text
npm ci
npm --prefix GentleHealersClient install --no-save
dotnet test GentleHealersApi.Tests/GentleHealersApi.Tests.csproj
node --test GentleHealersClient/src/features/treatmentCodes/access.node-test.js GentleHealersClient/src/services/treatmentCodeImport.node-test.js
npm --prefix GentleHealersClient run build
```

On the standalone US 10.1 branch, `install --no-save` resolves the optional entries missing from the inherited client lockfile. Team branches with the updated client lockfile can use `npm ci`. The `.node-test.js` extension keeps the Node tests separate from the team's Vitest discovery.

Run the existing API and Vue client, sign in as a system administrator, and use the dashboard's import link. `POST /api/admin/treatment-codes/import` expects multipart field `file`; `GET /api/treatment-codes` returns the current active codes for authenticated users. API validation errors return a Dutch `message`. Database failures return a generic 503 response without exposing SQL details.

### Selenium browser tests

The two Selenium test cases replace the Node.js checks with the same IDs. The first runs once with an Excel workbook and once with a CSV file. Each run imports a file and compares all five fields with the active catalogue. The second checks the validation message, disabled import button and unchanged catalogue when unsupported files are selected.

Run the local client and API against a disposable test database with the project schema and a test system-administrator account. The successful import replaces the active catalogue in that database. Chrome is required. Set `GENTLEHEALERS_BROWSER_TEST_URL` to the local client address and set `GENTLEHEALERS_BROWSER_TEST_EMAIL` and `GENTLEHEALERS_BROWSER_TEST_PASSWORD` to the test account's credentials.

```text
dotnet test GentleHealersApi.Tests/GentleHealersApi.Tests.csproj --filter TestCategory=Browser
```

The browser tests are skipped when the local client address is unset. The other 29 automated import tests run without a browser or database.

On 20 November 2026, both Selenium tests passed in Chrome against the real client and API with a fresh local SQL Server container. The remaining 14 backend tests and 13 Node.js tests also passed.

On 21 November 2026, the original `zorgbehandelingen.csv` imported 100 active treatment codes through the live API in an isolated SQL Server database.
