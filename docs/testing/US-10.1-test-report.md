# US 10.1 - Treatment-code import: test report

Date: 19 November 2026. Branch: `US-10.1-Zorgbehandelingenbestand-inlezen`.

## Implemented behaviour

An authenticated `SystemAdministrator` can select and import a real `.xlsx` or `.xls` workbook at `/admin/treatment-codes/import`. The page follows the supplied desktop wireframe and also works on a small screen. The existing login, JWT API client, router and SQL schema are reused.

The source header is `Zorgcode, Omschrijving, Specialisme, Tijdsduur (kwartieren), Kosten (€)`. One data row represents one treatment code. Duration remains a number of quarters; it is not converted to minutes. Costs are stored as `decimal(10,2)`. Required fields must fit the existing database constraints. Uploads are limited to 10 MB and 10,000 treatment rows.

The supplied source is CSV. A separate Excel copy containing exactly the same 100 records was used for the successful-import checks. The original CSV was not changed. CSV, PDF and files merely renamed to an Excel extension are rejected. Saving as an actual Excel workbook is required.

| Finding | Resolution and evidence |

## Running the checks

Use .NET 11, the project's Node/npm requirements and the existing GentleHealers database schema. Configure `ConnectionStrings:DefaultConnection` and the existing JWT settings for the intended local environment. Do not run the data seeder repeatedly.

From the repository root:

```text
npm ci
npm --prefix GentleHealersClient install --no-save
dotnet test GentleHealersApi.Tests/GentleHealersApi.Tests.csproj
node --test GentleHealersClient/src/features/treatmentCodes/access.node-test.js GentleHealersClient/src/services/treatmentCodeImport.node-test.js
npm --prefix GentleHealersClient run build
```

On the standalone US 10.1 branch, `install --no-save` resolves the optional entries missing from the inherited client lockfile. Team branches with the updated client lockfile can use `npm ci`. The `.node-test.js` extension keeps the Node tests separate from the team's Vitest discovery.

Run the existing API and Vue client, sign in as a system administrator, and use the dashboard's import link. `POST /api/admin/treatment-codes/import` expects multipart field `file`; `GET /api/treatment-codes` returns the current active codes for authenticated users. API validation errors return a Dutch `message`. Database failures return a generic 503 response without exposing SQL details.

The client entry point registers the import route and mounts a layout that shows the import page on its own. The dashboard links to the route for system administrators. The import route keeps its own access check, and the API enforces the same role on upload. The API changes include the SQL session-context key correction and the stable OpenAPI package. The root npm lockfile includes the entries required for a clean installation.

The Inter font is self-hosted only for this feature; its license is included beside the font asset. The source wireframes and project Word documents were not edited.
